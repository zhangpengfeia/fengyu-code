# V1.0 需求实施说明

本次以用户提供的《基于RuoYi-Vue3 智慧教育平台 开发需求说明书》V1.0为依据，在现有教育模块上增加业务能力。继续使用当前官方若依 3.9.2、MyBatis、原生角色菜单、操作日志、字典、参数、ExcelUtil 和 Quartz，不替换已有框架和登录安全实现。

## 已接入的业务

| 模块 | 实现内容 |

新增业务页面使用后台菜单生成路由，写操作配置 `v-hasPermi` 并在后端重新校验权限。学习服务共同校验学校、老师任教班级和学生本人范围。审计沿用原生 `@Log`。新业务表均包含原生审计字段、逻辑删除和版本号。

## 数据库升级

已有V003数据库依次执行：

1. `sql/V004__learning_business.sql`：扩展字段、业务表、参数、历史课件扩展数据回填和唯一索引。
2. `sql/V005__learning_menus.sql`：菜单、按钮、角色授权、字典和默认暂停的Quartz任务。

脚本只执行一次。正式升级前备份并在MySQL 8.0测试库验证。课件唯一索引会拒绝已有重复的同学校、学科、册次、名称记录，应先核对重复数据，不能通过删除业务历史来绕过。

H2开发环境由 `scripts/generate-dev-schema.py` 生成整库初始化脚本；重启即可获得新表、新菜单和字典。生产没有自动运行迁移，不会因为本次代码修改直接改变线上数据库。

原生任务管理中的调用目标为 `educationMaintenance.expire()`，每日执行，包含提醒与过期处理。任务默认暂停，确认服务器调度时区后启用。提醒日期按Asia/Shanghai计算，数据库时间保持UTC。资源访问实时检查有效期，不依赖定时任务及时运行。

## 外部依赖和未覆盖的文档细节

以下项目没有被标记为完成：

- 百度AI：`DubbingScorer` 是实际供应商适配器的接入点。尚无用户开通产品的协议、凭据和真实适配器；默认评分返回503，不写入伪造分数。适配器须将百度原始结果转换成20、20、15、15、15、15的六维评分。自定义权重当前拒绝启用。
- OSS：文件字段和原生上传组件已经接入，目前沿用若依已有文件上传端点。未配置对象存储、私有访问策略或签名下载，不能把本地上传称作OSS交付。
- 批量能力：账号Excel导入和密码重置、班级归档、配音记录和激活码Excel导出已接入。组织／课件／配音素材的批量导入、通用列表全量导出、导入逐行错误Excel仍需扩展；当前账号导入失败给出首个失败行并整批回滚。
- 组织树保留原有节点，通过原生部门管理维护省市区学校；没有自动重建已有部门树，未强制重写现有树为四层。
- 班级与学校范围使用业务统一校验；未引入新的通用注解或更换MyBatis-Plus，以避免修改框架核心。
- 字典已接入学科、课件阶次、数学能力、课堂评价、配音用途和PK阶次；部分关系型状态码仍为服务端固定合法集合。不是所有既有枚举都完成了字典迁移。
- 保留随机初始密码、已验证手机号才能登录和首次强制改密。需求文档中学生默认密码同时出现`ls12345678`和`12345678`，没有将冲突的共享密码写入实现。
