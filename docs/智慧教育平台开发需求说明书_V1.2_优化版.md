本平台为教育运营人员管理学校、账号、教学资源和学习权限，为老师提供课件、互动游戏与课堂PK，为学生提供已授权学习内容、激活兑换和配音记录。后续开发围绕“学校开通—账号入班—资源发布—授权学习—课堂互动—结果留存”完成业务闭环。

本版以现有页面为基础重新组织需求，保留原Word的业务目标，修正技术描述和冲突规则，补充页面交互、异常处理、数据约束与验收标准。**页面可见、接口存在、第三方接通和生产验收是四种不同状态，不得相互替代。**

“当前现状”依据本次仓库核对，不代表服务器已经部署同一版本；“目标要求”用于后续开发与验收，不能据此宣称功能已完成。文中建议默认值尚未形成业务决定的，在第十七章集中列出。

## 一 文档使用与实施范围

### 1.1 状态与优先级

| 标记     | 定义                                                             |
| -------- | ---------------------------------------------------------------- |
| 已接入   | 页面和相关业务接口已存在，可进入功能回归；不等于完成生产验收     |
| 部分接入 | 已有部分流程，仍缺页面、约束、运营能力或外部依赖                 |
| 仅接口   | 后端已有能力，当前没有完整的业务操作页面                         |
| 待接入   | 当前没有形成可用闭环，需要新增开发或接入外部服务                 |
| P0       | 正式业务使用前必须解决的权限、数据一致性、流程真实性或持久化问题 |
| P1       | 完善教学和运营效率的下一阶段功能                                 |
| P2       | 在核心流程稳定后实施的扩展能力                                   |

### 1.2 本版范围

覆盖组织学校、账号注册与管理、班级任教、课件与游戏、配音素材与评分、分组PK、积分榜、激活授权、审计运维和验收。

家长多孩统一账号、付费订单、收费结算、完整教学报表、跨校任教、游戏在线开发平台不纳入本轮默认范围。确需建设时建立独立需求，不复用学生账号或后台管理员账号拼接实现。

### 1.3 技术基线

| 层次       | 当前基线与要求                                                     |
| ---------- | ------------------------------------------------------------------ |
| 管理前端   | Vue3、Element Plus、Vite，沿用若依布局、动态菜单与权限指令         |
| 后端       | 当前若依3.9.2项目、Spring Boot 3、JDK 17、Spring Security、MyBatis |
| 业务模块   | 业务代码主要放在`ruoyi-education`，由启动模块装配                  |
| 正式数据   | MySQL 8.0及Redis方案，需实际迁移、备份和恢复验证                   |
| 当前演示   | H2内存库、单进程内存缓存；进程重启会清空业务数据和会话             |
| 文件       | 当前沿用原生上传端点；私有对象存储与签名访问待接入                 |
| 调度       | 复用`ruoyi-quartz`，请求级有效期检查始终保留                       |
| 第三方评分 | 通过`DubbingScorer`适配；尚无可用的真实百度评分适配器              |

不因Word中的技术名词而直接替换现有持久层；MyBatis-Plus并非完成本业务的前提。操作审计沿用`@Log`，按钮显隐使用`v-hasPermi`。逻辑删除与数据范围须落实到实际SQL和业务校验，不假定添加字段或注解即可自动生效。

### 2.2 不能仅凭页面认定已完成的能力

1. 配音素材、配置和记录页已经接入；学生录音、真实评分、失败任务恢复尚未形成生产闭环。
2. 榜单有班级与学校维度接口；当前课堂页主要展示当前班级、当前课件榜，尚无完整独立榜单中心。
3. 注册审核参数已经接入；当前主要通过账号停用状态承接待审核，缺专用审核状态、记录和审批页面。
4. 课件定制可以生成学校副本；来源追踪、默认覆盖展示、差异升级和恢复模板尚未完整实现。
5. 单次激活兑换和测评票据已接入；完整测评实例、素材版本锁定、明文码加密存储尚未完成。
6. 学校到期提醒已接入；后台任务默认暂停，须完成配置和实际投递验证。

## 三 角色与统一权限

### 3.1 角色职责

| 角色       | 数据范围           | 主要操作                                   | 明确限制                                       |
| ---------- | ------------------ | ------------------------------------------ | ---------------------------------------------- |
| 超级管理员 | 全平台             | 全局资源、角色菜单、参数、学校及运营配置   | 不绕过唯一性、事务和历史一致性约束             |
| 区域管理员 | 授权部门及下属学校 | 学校、班级、账号、授权和统计               | 不管理范围外学校，不提升自身或下级为上级管理员 |
| 学校管理员 | 本校               | 本校账号、班级、资源使用和允许委派的授权   | 默认不修改全局素材、测评规则及全局参数         |
| 老师       | 有效任教班级       | 课件预览、课堂表现、PK、班级分组、记录查看 | 默认无账号批量导入、批量重置、毕业归档权限     |
| 学生       | 本人及本人可用内容 | 课件与游戏使用、激活、配音、本人结果       | 不开放老师教学管理能力，不读取其他学生明细     |

省、市、区管理员可复用区域角色并配置不同部门数据范围；需要不同功能权限时再拆分角色，不把行政级别写死在前端。

### 3.2 三层校验

```mermaid
flowchart LR
    A[身份与登录会话] --> B[账号及学校有效]
    B --> C[功能权限]
    C --> D[学校和班级数据范围]
    D --> E[资源发布状态与用途]
    E --> F[学校资源池]
    F --> G[学生个人有效授权]
    G --> H[允许访问]
```

1. 功能权限控制是否可调用某类接口，菜单和按钮只提供交互辅助。
2. 数据范围控制可访问哪些学校、班级和对象；详情、写入、导出与批量处理均检查。
3. 资源授权控制可使用哪些学科、册次、课件或游戏。
4. 账号停用、学校无效、资源下架等条件优先拒绝；个人多条有效授权之间取并集。
5. 学生课件访问通常同时满足学校资源池和本人授权；老师管理预览、区域管理查看与学生学习不能共用未经区分的判断。
6. 学校资源池约束适用于课件及跟随课件授权的游戏。独立学生游戏目前按游戏直接授权判断，不应在页面中误称其已完成全部学校资源池校验；若要求统一，须扩展游戏资源池。

### 3.3 时效与错误反馈

- 有效期统一采用左闭右开区间：`开始时间 ≤ 服务端当前时间 < 到期时间`。
- 学校到期、账号冻结、角色变更、授权撤销后，后续访问须立即重新判断，不能等待每日任务。
- 未登录或会话失效返回401；无权限返回403；资源不存在按接口约定返回404；并发版本冲突返回409。
- 首次强制改密期间，业务请求被限制；当前教育接口使用428提示先改密。
- 页面提示应区分学校到期、账号冻结、资源未授权和资源下架；对登录失败继续使用统一提示，避免暴露账号存在性。

## 四 组织 学校与班级

### 4.1 组织结构

业务期望路径为省—市—区—学校，复用部门树维护；学校业务表与学校部门节点关联。现有数据不自动重建为四层，新增导入和调整流程必须校验父级关系、节点类型及管理范围。

学校名称用于展示，学校ID为稳定关联，学校编码用于专属入口。部门与学校存在重叠字段时明确唯一维护入口，禁止两个页面长期各自修改形成不同状态。

### 4.2 学校开通与到期

| 项目     | 目标要求                                        | 当前情况                                       |
| -------- | ----------------------------------------------- | ---------------------------------------------- |
| 建校     | 先建立学校部门节点，再维护学校业务信息          | 已接入                                         |
| 到期时间 | 新增／启用必填；启用时必须晚于当前时间          | 已接入，过去的截止时间返回业务错误             |
| 快捷天数 | 从本次操作时间计算，显示具体截止时间            | 已接入                                         |
| 人工停用 | 暂停学校范围内账号与资源访问，保留历史          | 已接入，恢复需有权限管理员操作                 |
| 自然到期 | 即使状态仍显示正常，也须立即拒绝访问            | 已接入，已覆盖等待真实到期的验收用例           |
| 前置提醒 | 提前7、3、1天通知学校管理员和上级运营，去重投递 | 部分接入，须启用调度并验证实际接收范围         |
| 续期     | 显示原截止与新截止、原因、操作人及时间          | 当前可编辑截止时间；独立续期记录待完善         |
| 状态区分 | 自然到期、人工停用和部门停用分开展示与存储      | 当前调度会把到期学校改为DISABLED，原因维度待补 |

**P0优化：**保留独立的人工停用标记，业务有效状态由账号、部门、学校人工状态和截止时间共同计算。续期只改变期限，不自动解除人工停用；迁移时无法判断停用原因的记录默认保留停用，交由管理员核对。

日期输入须说明“当日是否可用”。建议日期型截止按所选日期次日00:00的北京时间处理；当前精确到时分的时间输入保持实际所选时刻，不悄悄变更。

### 4.3 班级 任教与归档

- 班级包含学校、学年、年级、名称和正常／归档状态；同校、同学年、同年级班级名称唯一。
- 一个学生只有一个当前班级；老师可任教本校多个班级，关系有开始和结束时间。
- 转班／转校同时更新当前归属、关闭旧历史关系、建立新历史关系、调整当前分组；历史成绩与对战记录不改写。
- 学校学号按学校唯一，转校前检查目标学校学号冲突；不静默更换学号。
- 当前编辑页可直接修改学生学校，目标要求增加转校影响确认、原因和独立审计；是否需要两校审批见第十七章。
- 毕业归档前显示班级、学生数量和影响；归档后禁止继续授课与新增学习结果，关联学生登录停用，历史数据可查询。
- 当前归档会停用关联学生并保留数据；当前关系是否终止及是否允许恢复，应补充独立流程，不通过直接修改数据库恢复。

## 五 登录 注册与账号管理

### 5.1 身份与登录标识

自然人账号统一以`sys_user.user_id`为身份。学生内部账号稳定生成，学号使用字符串，保留前导零；不能把可能跨校重复的学号直接用作全局账号。

登录页保留明确的账号、手机号、学校学号三种模式。当前自动识别作为填写辅助；用户手动选定后不再覆盖选择。形态冲突时允许明确切换，不依据输入形态改变角色或授予权限。

学校专属链接只锁定学校选择，不产生额外权限。浏览器可记忆上次学校，不存明文密码。手机号只有完成号码归属验证且与当前账号号码一致时才可用于登录。

### 5.2 注册与审核

现有流程：选择省市区学校与班级 → 学号、姓名、可选手机号 → 密码与确认 → 验证码 → 提交。前端不提供身份选择，后端固定学生角色，忽略或拒绝提权字段。

| 规则       | 当前情况                                             | 优化要求                                                              |
| ---------- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| 学校与班级 | 仅选择有效学校和正常班级                             | 保持，后端再次校验归属                                                |
| 学校＋学号 | 数据库唯一兜底                                       | 重复提示不得产生残留账号                                              |
| 手机号     | 可选、非空唯一；登记不等于验证                       | 保持，后续接入真实短信                                                |
| 注册审核   | `biz.student.register.audit`默认关闭；开启后账号停用 | 正式开放前建议开启审核，新增PENDING／APPROVED／REJECTED状态和审核记录 |
| 身份可信度 | 目前可自选学校班级                                   | 增加名单核验或班级邀请码，避免冒用真实学生学号                        |
| 入班分组   | 注册后加入默认分组                                   | 审核模式下，建议审核通过后再纳入正式教学名单和分组                    |

### 5.3 用户管理

统一用户页通过身份筛选管理老师、学生、学校管理员。主要操作为新增、详情、编辑、冻结／启用、单个重置、批量导入与批量重置。

学生编辑包含学号、学校、班级、当前册次、试用标记；老师编辑包含任教班级。学校管理员仅可委派允许的本校角色。老师查看有效任教班学生，默认不具备批量修改账号权限。

目标要求补齐班级／状态筛选、账号审核、归属变更记录、授权查看和影响说明。冻结账号、离职处理与业务记录归档分开管理。

### 5.4 密码与短信

1. 取消Word中前后冲突的共享默认密码，以当前随机临时密码为基线。
2. 新建／导入账号及密码重置后强制改密；学生自主注册自行设置的密码不作为临时密码。
3. 当前密码规则为8至32位、至少两类字符；与登录端限制保持一致。
4. 批量重置支持每人随机密码或统一自定义密码，操作前确认影响，结果仅授权人员查看。
5. 修改密码立即使旧Bearer和原游戏会话失效；密码、完整Token、验证码不写入操作日志。
6. 正式短信未接入时明确提示不可用；开发环境模拟验证码不得进入生产。忘记密码当前由有权限管理员重置，不宣传已支持短信找回。

### 5.5 Excel导入

当前采用一个账号模板，以身份字段分发老师和学生；单次1至1000行、文件不超过5MB，支持跳过重复和覆盖更新。学生按学校＋学号、老师按账号判重，主表与业务表在整批事务内保存，首个失败行会导致整批回滚。

目标要求：

- 可保留统一模板，但下载时提供老师／学生填写示例及必填提示。
- 先展示预校验结果，再确认导入；反馈成功、失败、跳过数量。
- 覆盖默认只更新允许字段，不覆盖密码、角色、积分、审核结果，不借导入静默转校、解冻账号或重建任教关系。
- 每行独立检查学校、班级、角色委派、手机号和唯一性；导入范围不能仅检查第一行。
- 提供逐行错误Excel及任务号；文件只对提交人和授权管理人员可见，并配置清理期限。

### 6.2 学校定制与版本

已有“学校定制”操作可从全局模板生成本校草稿。后续要求记录来源模板ID与来源版本；本校发布副本优先展示，但不能覆盖其他学校或修改全局模板。

全局模板升级不得自动覆盖学校编辑内容。升级页面展示差异，学校确认后生成新编辑稿；发布形成新快照。恢复模板仅调整生效版本或覆盖关系，不删除学校历史副本。

当前快照已包含基础字段、游戏关联和学科扩展；学习记录、配音、PK还需保存发生时的课件版本及素材版本，防止内容更新后无法追溯当时依据。

### 6.3 数学课件

| 区块     | 页面字段与要求                                                       |
| -------- | -------------------------------------------------------------------- |
| 基础信息 | 名称、学校、册次、封面、排序、状态                                   |

| 互动游戏 | 优先从统一游戏目录关联，避免散落的永久外链                           |

### 6.4 阅读课件

- 选择本册、启用且有课件用途的配音素材；测评专用素材不能作为课件素材。
- 当前素材可被多个同册课件引用，数据库没有一对一限制；建议保留复用，若坚持一对一须补唯一约束和更换流程。
- 当前JSON编辑器支持语法校验、格式化和高亮预览；尚不等于已支持完整学习流程执行。
- 目标为流程配置增加Schema版本，校验步骤类型、次序、引用资源和必填字段；禁止配置任意脚本、任意组件或不受控URL。
- 老师预览与学生学习分开鉴权；学生端按已发布版本渲染流程，不直接运行管理端编辑稿。

### 6.5 文件管理

当前封面、视频、PDF沿用原生上传与URL字段。正式目标为统一文件记录、私有对象存储、文件用途和短期签名访问；业务表保存稳定文件ID，不长期保存会过期的签名地址。

上传校验类型、内容、大小与归属；录音、教材和教师资料按使用者身份鉴权。历史版本引用文件保留，替换文件不能使旧记录失去依据。对象存储适配、正式短信和真实评分均为独立接入事项，不以增加配置项视为完成。

## 七 游戏目录与接入

### 7.1 游戏独立建档

游戏与课件分开维护，一个课件可关联多个游戏，一个游戏可被多个课件引用。游戏字段包含唯一编码、名称、分类、接入方式、入口、版本、说明、排序、发布状态与访问策略。

| 维度     | 当前取值     | 业务含义                                                 |
| -------- | ------------ | -------------------------------------------------------- |
| 接入方式 | INTERNAL     | 可信内部游戏，版本目录和静态资产受网关保护               |
| 接入方式 | EXTERNAL     | 白名单HTTPS外链；目前只能控制后台入口                    |
| 访问策略 | TEACHER_ONLY | 老师及允许的管理身份使用，学生即使持有其他授权也不能进入 |
| 访问策略 | COURSEWARE   | 通过可用关联课件判断，遵循课件资源池与学生权限           |
| 访问策略 | STUDENT      | 面向学生独立授权，不能由一次课件关联自动扩权             |

### 7.2 内部游戏保护

当前内部游戏使用60秒单次票据，交换为30分钟游戏会话；父登录会话、账号、学校、密码和资源权限在访问时重新校验。HTML、脚本及静态资源同样受保护，票据不可重放，某个游戏的会话不能访问另一个游戏。

发布前须构建对应版本、入口文件和匹配清单。后台不提供任意源码上传并立即公开运行的通用入口。

当前后台与可信内部游戏采用同源路径，**不具备浏览器来源隔离**。本版不把它描述成沙箱。第三方不可信HTML必须采用独立来源或专门隔离方案后接入。

### 7.3 外部游戏与后续回调

外部游戏页面明确显示“仅控制平台入口，对方公网地址不受本平台保护”。后续若供应商支持SSO或一次性票据，需单独对接并验收，不能只隐藏地址就宣称受保护。

游戏积分回调默认不开放正式入账；后续接口须验证来源签名、学生身份、课件与课时、事件幂等和分值规则。前端传入总分或星数不能直接成为正式积分。

## 八 配音素材 测评与评分

### 8.1 素材库

当前素材包含册次、标题、视频、文本、用途标签、状态和说明。册次范围1至12，同册标题唯一；当前写操作仅超级管理员开放。

用途编码沿用：01课件配套、02测评专用、03通用。当前为字符串多标签兼容存储，目标可规范为素材—用途关系表；迁移保持原标签语义，“通用”同时满足课件与测评用途。

当前素材页提供册次与标题查询，标签和状态已有接口筛选能力，页面筛选待补。新增批量导入、素材发布版本和引用关系查询，修改文本或视频不能悄悄改变旧评分依据。

被课件引用的素材当前不能随意停用、移册或移除课件用途；删除采用逻辑删除，已有记录不得丢失引用。

### 8.2 测评配置

| 配置项   | 当前默认与限制                                     | 目标要求                                             |
| -------- | -------------------------------------------------- | ---------------------------------------------------- |
| 配置范围 | 每册一条，已初始化12册                             | 保持册次唯一，保存配置版本                           |
| 抽题范围 | 仅课件配套／仅测评专用／全部；通用素材参与匹配范围 | 明确显示候选素材数量                                 |
| 抽题数量 | 默认1，当前1至100                                  | 超出有效候选数量时阻止保存或抽题并说明原因           |
| 抽题方式 | 完全随机／排除已做随机                             | “已做”明确为已成功提交的测评结果及配置的历史范围     |
| 评分规则 | 与课件一致                                         | 自定义权重需结构化规则、总和校验、版本与真实适配支持 |
| 管理权限 | 超级管理员可修改，学校与老师按授权只读             | 不因拿到页面地址而获得写权限                         |

当前题量不足会返回错误，不跨册、不静默改数量。本版暂保留此行为；如运营要求“使用剩余题”，增加明确配置和前端提示后实施。

### 8.3 当前册与可学习册次

当前学生素材与抽题按后台管理的`current_volume`过滤，当前册不应由学生任意提交覆盖。

目标为“学习入口选择＋有效授权范围＋学校资源池”共同确定可学习册次，允许有多个册次权限的学生切换；当前册只作为默认位置，不扩大本人授权。该变更需同步素材查询、测评抽题、课堂配音与学生页面，不能只放开一个接口。

### 8.4 测评实例与票据

当前每次抽题生成绑定学生和素材的30分钟票据；成功写入后再次提交同一票据返回已有记录，不重复生成成绩。尚无完整测评实例和刷新续做页面。

P1目标：

1. 创建测评实例时固定配置版本、题目清单和素材版本。
2. 刷新或重新进入未结束实例恢复原题；主动换题须有次数与状态规则。
3. 展示未开始、进行中、已提交、已完成、已失效；有效期由服务端判断。
4. 他人票据、过期票据、素材不匹配及跨册请求均被拒绝。
5. 重新测评产生新实例，不覆盖历史成绩。

### 8.5 评分接入与分值

**当前真实评分供应商未接通。**后端已有适配契约、分值校验及记录写入流程；未提供有效适配器时返回503，不能用前端分值或模拟结果替代真实成绩。

| 评分维度 | 当前业务满分 |
| -------- | ------------ |
| 准确度   | 20           |
| 流畅度   | 20           |
| 完整性   | 15           |
| 声韵     | 15           |
| 语调     | 15           |
| 整体印象 | 15           |
| 总分     | 100          |

接入前用真实录音确认百度实际开通产品是否支持目标语言、年龄、录音格式及相应维度。语音识别不等于朗读评分；供应商缺少的维度必须调整业务规则或给出经过评审的计算依据，不能编造。

总分和星级由后端计算；当前星级默认门槛60、75、90，对应1、2、3星，低于60为0星。规则变更保留版本，历史结果不自动重算。

目标增加评分任务状态：待处理、处理中、成功、失败。失败与未评分的分值应为空，不能写0分冒充已评分。异常保留脱敏原因与供应商请求号，提供有限重试、状态恢复及人工重评；重评生成新结果版本。

“同一结果只入账一次”通过业务幂等实现；网络超时下不承诺供应商调用绝对只发生一次，须结合查询与调用费用控制。

### 8.6 学生操作与记录页

目标学习流程为：进入授权课件／测评 → 播放素材 → 麦克风授权 → 录音、试听、重录 → 上传确认 → 提交评分 → 查看处理中或结果。

当前尚无完整学生录音与异步评分页面，该流程按待接入验收。学校使用的浏览器须实际验证HTTPS、麦克风权限、音频格式、上传重试和弱网恢复。

配音记录共用列表与详情：课件配音显示百分制，测评显示星数并可查看总分；展示学校、班级、学生、册次、素材、时间、录音和可用评分明细。当前已接入班级／册次／类型查询、详情和Excel导出，学校／素材／评分状态筛选、排序与安全播放仍需补齐。

## 九 课堂分组与PK

### 9.1 当前入口与目标入口

当前为独立“课堂PK与积分”页面，先选择任教班级和已发布课件，再使用课堂表现、对战、小组管理三个页签；顶部可展开当前课件积分榜。

目标增加课件列表／预览中的“进入课堂”入口，自动带入课件，保留独立课堂页；是否采用弹窗由终端体验决定，不重复建设两套结算逻辑。

### 9.2 班级分组

- 新生默认加入未满小组，默认4人，可通过参数配置为2至6人。
- 随机重分支持2至6人，生成新当前分组，旧小组与成员关系标记历史。
- 支持新增小组、手动调组、删除并转移成员；删除前必须选择本班其他有效小组接收成员。
- 分组为班级公共能力，课件之间共用；PK按对阵开始时的成员快照结算，后续调组不改变旧对战获奖名单。
- 当前使用`is_current`管理历史，后续增加分组方案版本及数据库唯一约束，保证一个方案内学生不能同时属于两个小组。
- 班级切换、归档、学生转出和账号停用时及时更新可参赛名单，历史成员快照保持不变。

### 9.3 课件阶次与PK难度分开

| 概念     | 作用                     | 当前编码                          |
| -------- | ------------------------ | --------------------------------- |
| 课件阶次 | 教学资源内容分类         | BASIC、LEVEL1、LEVEL2、LEVEL3     |
| PK难度   | 数学小组赛解锁与奖励梯度 | BASIC新手、LEVEL2能手、LEVEL3大师 |

两者即使部分编码相同，也不是同一字段或同一业务含义。选择一阶课件不等于自动解锁能手难度。

### 9.4 匹配 晋级与结束

| 场景           | 本版实施规则                                                 |
| -------------- | ------------------------------------------------------------ |
| 匹配入口       | 仅保留整体随机匹配，一次生成该轮全部对阵并落库               |
| 最低人数       | 至少2名学生或2个非空小组                                     |
| 首轮奇数       | 随机1名学生或1组轮空，自动晋级，轮空不加对战积分             |
| 后续奇数       | 当前从上一轮失败方随机补1名／组凑偶数，本版保留为兼容基线    |
| 当前轮未完成   | 阻止生成下一轮，提示待结算对阵                               |
| 剩余1个晋级方  | 赛程结束，目标页面明确展示最终胜者，不继续补位无限开赛       |
| 分组／人员变化 | 已生成对阵按快照保留；新一轮资格冲突时提示清空赛程后重新开始 |

V1.1 Word建议默认关闭失败方补位，与V1.0及当前实现不同。本版不静默更改已实现赛制。后续将补位做成显式配置，页面标注补位身份，并明确每轮补位人数、重复资格与获奖上限后再切换。

### 9.5 个人PK与课堂表现

个人PK适用于全部学科。倾听、思考、发言等评价项从字典读取；支持单人加减分、全体加分，均调用统一积分服务。

个人对战胜者默认加1分。课堂页展示本课件的课堂表现与对战累计，切换班级或课件必须重新加载，不沿用上一选择的名单和分数。

### 9.6 小组PK

数学小组默认新手阶，完成上一阶至少一轮完整对战后才能进入下一阶；新手、能手、大师默认每人奖励1、2、3分，可配置。其他科目使用基础难度。

小组本身不设永久积分余额，胜者奖励同步到该场参赛快照中的每位学生个人账户。一次小组结算必须全部成功或全部回滚。清空已完成赛程不应抹去已经取得的难度解锁资格。

### 9.7 撤销与清空

- 误判胜负使用撤销或更正，按原奖励分值生成反向流水，不按当前参数重新扣分。
- 已生成后续轮次时，当前禁止直接更改前置胜负；页面说明依赖关系，不通过先删流水绕过。
- 清空本轮数据只重置赛程，已加积分不回滚；确认弹窗必须说明此效果。
- “撤销本课时全部积分”如需提供，属于独立高权限操作，不能与清空赛程共用按钮。
- 当前赛程按班级、课件、模式和难度隔离，尚未形成每次上课独立课时。目标新增课时实例，避免同一课件多次授课覆盖赛程或混淆操作记录。

## 十 积分与榜单

### 10.1 统一记账

当前已有积分流水、反向记录、事件唯一键、学生行锁，以及总分、册次和年级JSON汇总。流水是核对依据，汇总用于查询加速；业务人员不直接修改或删除历史流水。

每次变更保存学生、发生时学校／班级／年级、课件、学科、册次、难度、分值、来源、操作人、时间及撤销关联。后续补齐课时、学年、课件版本和规则版本。

目标增加父事件和统一请求号，使全班加分、小组结算、游戏回调可审计、可重试且只入账一次。当前全班加分在同一事务内执行，但每次请求会生成新的随机事件键，**不能认定已经防止跨请求重复加分**，列为P0修复项。

### 10.2 分数与撤销

当前单次手动变更限制为-100至100且不为0，账户没有统一“不低于0”限制。建议正式业务默认不允许余额扣成负数，并由统一服务校验；是否允许负分须在上线前确认，不能仅靠页面限制。

撤销关联原流水，禁止重复撤销。历史学生转班后仍需有受控的原事件更正流程；当前按当前班级进行部分校验，跨历史归属更正尚不完整。

提供流水分页、筛选、导出、汇总对账和从流水重建汇总能力。自动核对发现差异应告警并留痕，不静默覆盖历史事实。

### 10.3 榜单口径

| 榜单         | 目标统计维度                 | 当前情况                                       |
| ------------ | ---------------------------- | ---------------------------------------------- |
| 班级课件榜   | 指定班级、课件、可选课时     | 当前课堂页已接入班级课件榜                     |
| 班级册次榜   | 指定班级、册次、学科范围     | 有接口筛选能力，完整页面待补                   |
| 年级学期榜   | 学校、学年、年级、学期／册次 | 有学校＋年级／册次接口，尚缺完整学年口径和页面 |
| 全校总榜     | 本校发生的正式积分           | 有接口，完整榜单中心待补                       |
| 学生个人总分 | 学生本人允许展示的跨历史累计 | 有汇总与流水，独立学生展示待完善               |

目标按事件发生时归属统计组织榜；学生转校不把旧校积分迁入新校榜。当前榜单同时筛选学生当前学校／班级，历史转班转校后可能改变榜单成员，尚未完全实现历史口径。

试用账号默认不进入官方榜；正式目标在事件中记录当时的试用／正式资格，避免后续改变账号标记而追溯改变成绩。同分建议同名次，后台固定次级排序；页面当前序号不应被直接认定为并列排名规则。

### 10.4 更新方式

当前页面在操作完成或点击刷新后重新查询，不是跨终端实时推送。目标普通教学操作完成后及时刷新；若提出“不超过5秒”的多人榜单更新要求，需补轮询或推送并进行实际测试。

## 十一 学校资源池与学生授权

### 11.1 两层授权

学校资源池表示学校具备哪些资源使用范围，学生授权表示学生本人可使用其中哪些内容。全局模板可被配置使用，不代表所有学生自动获得学习权限。

当前资源池页面以学科、册次和有效期为主；精确到课件的配置需增加清晰的选择入口。新建学校不能隐式开放全量资源，演示套餐应显式初始化。

### 11.2 权限类型

| 类型       | 业务范围               | 当前实现及后续约束                                                            |
| ---------- | ---------------------- | ----------------------------------------------------------------------------- |
| 单课件     | 指定课件               | 校验发布状态与目标学生学校归属                                                |
| 独立游戏   | 指定允许学生使用的游戏 | 不得给学生授予TEACHER_ONLY游戏                                                |
| 学期型     | 当前册次＋学校开通学科 | 兑换／发放时固化当前册次，不因之后改当前册而漂移                              |
| 指定范围型 | 册次、学科、阶次组合   | 当前使用JSON，目标改为多选控件并显示最终范围                                  |
| 全量型     | 明确约定的全册全科范围 | 当前ANY匹配会覆盖未来新增符合资源；目标显式选择是否包含未来资源，默认范围快照 |

授权须保存来源、范围、起止时间、状态、原因和操作人。多条有效授权取并集，撤销其中一条不能覆盖其他仍有效的独立授权。

### 11.3 转校 撤销与续期

转校只变更当前组织关系，不直接改写已发授权的来源和历史范围；访问时重新检查目标学校资源池和必要的学校绑定限制。

人工撤销填写原因，后续访问立即生效。续期新增授权或续期事件，保留原记录；不直接覆盖历史起止时间、来源或兑换人。

## 十二 激活码运营

### 12.1 批次发行

当前可配置批次名称、权限类型、范围JSON、数量、授权天数、批次到期和可选学校ID。单批数量1至10000，授权天数1至3650；默认180天。学校绑定受系统参数控制，未开启时不能提交学校限制。

目标增加学校与范围选择器、批次搜索、状态筛选、明细查询、使用率和异常记录；不要求运营人员手填JSON或记忆学校ID。

### 12.2 兑换与时间

1. 区分“批次兑换截止时间”和“兑换后学习权限到期时间”。
2. 在批次截止前成功兑换，从兑换时刻计算完整授权天数；批次之后到期不追溯缩短已发权限。
3. 激活码与批次有效、学校匹配、当前学生有效后才可兑换。
4. 同一码通过行锁／条件更新保证只使用一次，绑定学生、生成授权、计数更新在同一事务中完成。
5. 重复兑换提示已使用或返回既有结果，不重复发权；页面阻止重复提交仅是辅助。
6. 未使用码随批次到期失效；已兑换授权按自身截止时间判断。学校停用仍会阻止学习。

### 12.3 导出与安全边界

当前支持按批次导出Excel，后台保存可重复导出的明文码。本版明确该现状，不将其描述成已做哈希或加密。

正式批量发行前，确定一次性明文导出或可恢复密文存储方案；码明文不进入审计日志。生成、查询明细、导出、作废分别控制权限，记录操作人、批次、数量和结果。

如需停发、批次撤销、未使用码作废或重新生成，应定义独立流程，禁止删除已兑换记录或把旧码改回未使用。

## 十三 通用页面与运营规范

### 13.1 列表与表单

- 列表统一查询、重置、刷新、分页和空状态；只展示当前权限内的学校、班级和资源选项。
- 查询条件名称与数据口径一致，切换条件回到第一页；固定学科页面不允许选择与其范围矛盾的学科。
- 新增、编辑、查看分开；详情不因按钮隐藏就免除后端检查。
- 表单区分必填、选填、默认值与条件必填，提交时显示明确字段错误；原生资源选择器优先于手工输入ID。
- 高风险操作说明影响范围；保存期间防重复提交，服务端仍执行并发和幂等控制。
- 409版本冲突提示刷新并重新确认，不自动覆盖新版本；上传、评分和批处理显示进行中、失败和恢复方式。
- 禁止用“成功”提示掩盖部分失败；异步操作成功受理与最终完成分开显示。

### 14.2 统一字段与兼容

- 原生用户身份统一为`user_id`。现有学习表中的`student_id`实际指向该用户身份，不额外创建一套自然人ID；接口文档必须标明含义。后续规范命名采用版本兼容迁移，不直接批量改名。
- 主键使用bigint，JSON中以字符串传递；学号、手机号、学校和游戏编码不能按数值运算。
- 数据库存储UTC时刻，界面以北京时间展示；有效期以服务端判定。
- 普通可修改业务实体使用创建、更新、说明、逻辑删除及必要版本字段；积分、兑换等事实记录通过补偿事件更正，不开放普通删除入口。
- 账号、学校编码、游戏编码、学校学号等稳定标识删除后默认保留，不自动分配给另一个对象。
- 当前课件唯一约束通过规范化学校范围处理全局NULL语义；发布前保留同范围唯一性校验。
- 索引以实际学校、班级、册次、时间和分页SQL设计，结合执行计划验证，不要求所有字段机械添加单列索引。

### 14.3 接口约定

业务接口统一置于`/biz`。列表沿用`code/rows/total`，详情沿用`code/msg/data`；默认每页20，普通分页最大100。批量和导出定义各自容量及任务策略，不无限放开普通列表上限。

新增修改使用白名单字段映射；排序字段受控，禁止把客户端字段名直接拼入SQL。学校、班级、学生、积分和操作人不能仅按前端传值确定。

接口权限标识沿用`biz:模块:动作`。发布、预览、密码重置、授权、导入导出等动作按风险拆分；现有共用权限若过宽，迁移时保留原角色能力并逐步收敛。

## 十五 部署与非功能要求

### 15.1 环境与迁移

1. 开发演示与正式业务环境分开；H2内存演示不承担真实学生资料、成绩或长期运营数据。
2. 正式使用前验证MySQL持久化、Redis、对象存储及备份恢复，保证重启不丢业务记录。
3. 空库按V001至V005顺序初始化；已有V003数据库只执行后续增量，不重导原生基线。
4. 当前V004／V005需一次性执行；后续改动另加新迁移，不回改已在线执行的脚本。
5. 上线前检查重复课件名称等约束冲突；备份与回滚不能依靠删除业务历史解决。
6. 部署完成须核对发布版本与健康检查；本地构建成功不代表线上已经生效。

### 15.2 调度职责

当前任务目标为`educationMaintenance.expire()`，默认暂停。职责为学校提醒、学校到期状态维护、个人授权和未用激活码过期。启用前确认调度时区、执行账号和接收人配置，提醒按Asia/Shanghai日期计算。

后续增加积分对账、评分超时恢复、临时上传和导出清理任务。所有任务有执行日志、幂等和失败追踪；访问权限实时校验不依赖调度准时执行。

### 15.3 安全与恢复

正式环境使用HTTPS，数据库、Redis和对象存储密钥由受控环境注入。仓库与需求文档不写实际服务器密码、Token或供应商密钥。

同源可信游戏保持现有保护；不可信第三方内容另行隔离。导出、音频播放、教师资料下载检查与查询相同的数据范围。备份覆盖数据库、业务文件与必要配置，定期演练恢复。

建议备份恢复目标为RPO不超过24小时、RTO不超过4小时，须按学校业务与运维成本确认，不能作为尚未验证的服务承诺。

### 15.4 浏览器与性能

- 目标覆盖Chrome及学校实际使用的360、QQ浏览器Chromium模式，最低版本按设备清单确认；不默认支持IE兼容模式。
- 录音另测HTTPS、麦克风权限、设备切换、音频格式、长录音、弱网和后台切换。
- 建议压测场景为100所学校、10万学生、100万积分流水、100个并发活跃用户；须记录硬件、数据分布和网络条件。
- 建议普通列表和权限校验P95不超过1秒；榜单更新若要求5秒内可见，须补对应刷新机制和验证。
- 第三方评分、媒体下载与大导出单独定义指标。上述为拟定测试目标，不是当前已验证容量。
